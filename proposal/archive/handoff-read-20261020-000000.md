## Where we are
We're designing how the User and several agents can work together around a **live preview**
of educational maths/science apps, keeping running cost under control. Nothing is built,
tested or measured. Full details: `../deferred/agent-room-visual-harness.md` (main proposal),
`../deferred/crit-vibeyard.md` (tool research), `../deferred/edu-app-tooling.md` (background), `drawings/`.

## Proposed by agents (not decided)
- **Loop:** point at the preview → discuss with the room (no edits) → User explicitly hands
  the change to a worker → worker reports back → watch the preview update.
- **Context on request:** pointing attaches a short reference to the User's message; code,
  values or a cropped image are fetched only by the agent that needs them.
- **Pointing at moving objects** (the main uncertainty):
  - The app could name its own objects (`particleB`) so references survive moves and reloads
    (Claude). Selecting the right object and keeping its identity are separate problems
    (Codex).
  - Highlight the selection before sending so the User can correct it. If B is removed or
    replaced, say "original object unavailable" rather than re-attaching silently (Codex).
  - Pausing on click may not freeze the frame the User meant, and can hide the motion
    being discussed. Alternative: the highlight follows B as playback resumes (Codex).
- **Worker hand-off:** "Make the selected B bounce with energy loss; reference from preview
  v3." Worker reports what changed, which checks actually ran, the new preview version, and
  whether B is still identifiable (Codex).
- **Existing tools:** Crit (comment pins on a running app, file-based feedback) is the first
  candidate to evaluate; Vibeyard offers sending to an existing agent session. Both point
  at DOM elements; the checked documentation does not establish picking individual objects
  inside a canvas (documentation checked by Codex, links in `../deferred/crit-vibeyard.md`; not exercised).
- **Smallest trial** (outside this room): three named dots that cross and overlap, drawn
  once as SVG and once as canvas, both in Crit. Measure correct selections over ~20 clicks,
  whether B survives a reload, and whether removing B is reported honestly. Build custom
  picking only for what turns out to be missing.
  Also measure mismatch between the intended frame and the paused frame. SVG support,
  reference continuity and cost savings remain hypotheses, not established capabilities.
